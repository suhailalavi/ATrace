# AlaviTrace Operational Security Boundaries & Ethical Guardrails (v1.0.0)

AlaviTrace is engineered specifically for authorized vulnerability reconnaissance and controlled assessment. It explicitly prohibits destructive testing, automated exploitation, or invasive techniques.

---

## 1. Prohibited Actions (Non-Exploitation Policy)

The following activities are strictly out of scope and intentionally absent from the codebase:

1. **Remote Code Execution (RCE)**: No shell payloads, command execution strings, or reverse shells are ever executed against target assets.
2. **Credential Attacks**: Automated password brute-forcing, dictionary spraying, credential stuffing, and login cracking are strictly prohibited.
3. **Destructive Data Manipulation**: No SQL `DROP`, `DELETE`, `UPDATE`, or `INSERT` operations are performed. Database probing is limited to error pattern detection.
4. **Denial of Service (DoS)**: Rate-limiting, low concurrency, and explicit timeouts prevent target exhaustion. Flood attacks, slowloris, and amplification attacks are prohibited.
5. **Session Hijacking / Privilege Escalation**: Automated session hijacking, token forging, or administrative role assumption is not performed.
6. **Out-of-Band SSRF Calls**: AlaviTrace does not trigger out-of-band network callbacks to external infrastructure to avoid unintended intranet exposure.

---

## 2. Authorization & Scope Constraints

- **Single Target Scoping**: Assessments are restricted exclusively to the validated target host. External third-party CDNs, DNS services, and third-party APIs encountered during crawling are strictly filtered out of testing scope.
- **Controlled Request Limits**:
  - Attack Surface Mapper: Defaults to max depth 2, max 20 HTTP requests.
  - Controlled Validation Engine: Defaults to max 10 validation requests per finding, 5.0s timeout per probe.
  - Safe Headers: Requests carry explicit `User-Agent: AlaviTrace/<version> (Authorized Security Assessment)` headers for auditability.

---

## 3. Human-in-the-Loop Verification Principle

All findings generated by AlaviTrace represent prioritized investigation candidates:
- An NVD CVE correlation indicates that the detected software product and version have known historical vulnerabilities; it does not prove active target exploitability.
- A `VALIDATED` finding indicates that specific deterministic indicators (such as unencoded parameter reflection or SQL syntax error messages) were observed.
- Final confirmation of exploitability, business impact, and remediation urgency requires authorized human security engineers.
